# Mini NPU Simulator (3주차 미션)

NumPy 등 외부 라이브러리 없이 Python 표준 라이브러리(`json`, `time`)와 반복문만으로 AI 전용 칩(NPU)의 핵심 연산인 **MAC(Multiply-Accumulate)**을 구현하고, 패턴 판별 및 크기에 따른 성능 변화를 분석한 콘솔 시뮬레이터입니다.

## 1. 실행 방법

- **개발 환경:** Python 3.8 이상 (외부 라이브러리 미사용)
- **파일 배치:** `main.py`와 `data.json`을 동일한 디렉토리에 위치시킵니다.
- **실행 명령어:**
  ```bash
  python3 main.py
  ```
- **모드 선택:**
  - `1`: 사용자 입력 (3×3) — 필터 A, B와 패턴을 공백 구분으로 한 줄씩 입력하여 판정
  - `2`: `data.json` 분석 — 5×5, 13×13, 25×25 필터 및 패턴 일괄 검증, 성능 측정, 결과 요약 출력
  - `0`: 시뮬레이터 종료

## 2. 구현 요약

- **MAC 연산 (`mac_operation`):** $N \times N$ 2차원 리스트를 이중 `for`문으로 순회하며 같은 위치의 패턴 값과 필터 값을 곱해 누적합을 계산합니다. 연산 전 행/열 크기 일치 여부를 검증하며, 불일치 시 `ValueError`를 발생시켜 프로그램 중단 없이 해당 케이스만 `FAIL` 처리합니다.
- **라벨 정규화 (`normalize_label`):** `data.json`의 `expected` 값(`"+"`, `"x"`)과 필터 키(`"cross"`, `"x"`)를 내부 표준 라벨(`Cross`, `X`)로 통일하여 비교 및 출력의 일관성을 확보했습니다.
- **허용오차 기반 비교 정책 (`compare_scores`):** 부동소수점 연산 오차로 인한 오판정을 방지하기 위해 `EPSILON = 1e-9`를 적용했습니다. `abs(score_a - score_b) < 1e-9`인 경우 어느 한쪽의 우위를 단정하지 않고 `UNDECIDED`(동점)로 판정합니다.
- **성능 측정 (`measure_mac_time`):** 입출력(I/O) 시간을 제외하고 순수 `mac_operation` 호출 구간만 `time.perf_counter()`로 10회 반복 측정하여 평균 연산 시간(ms)을 산출합니다.

## 3. 결과 리포트

### 3-1. `data.json` 분석 및 실패 원인 분석

총 6개의 테스트 케이스 중 **3개 PASS, 3개 FAIL**이 발생했습니다. 실패한 3개 케이스(`size_5_1`, `size_13_2`, `size_25_1`)의 원인을 유형별로 분리해 진단한 결과는 다음과 같습니다.

1. **데이터/스키마 문제 여부 (해당 없음):** 모든 필터(`size_5`, `size_13`, `size_25`)와 패턴의 행/열 크기가 정상적으로 일치했으며, 라벨 정규화(`+`/`cross` → `Cross`, `x` → `X`) 또한 오류 없이 수행되었습니다.
2. **로직 구현 문제 여부 (해당 없음):** `size_5_2`, `size_13_1`, `size_25_2` 케이스가 정상적으로 `PASS` 처리되었으며, 3×3 수동 입력 테스트에서도 정확한 MAC 점수가 산출되었습니다.
3. **수치 비교 및 동점 정책 문제 (직접 원인):** 실패한 `size_5_1`, `size_13_2`, `size_25_1` 세 케이스 모두 `Cross` 필터 점수와 `X` 필터 점수의 차이가 허용오차(`1e-9`) 미만으로 계산되어 `UNDECIDED`로 판정되었고, 이에 따라 기대값(`expected`)과 불일치하여 `FAIL`로 기록되었습니다.
4. **시사점:** 부동소수점 미세 오차를 그대로 대소 비교(`>`)했다면 우연히 맞거나 틀리는 비결정적 결과가 나왔을 것입니다. 허용오차(`epsilon`) 기반 동점 정책을 적용함으로써 판별력이 부족한 필터·패턴 조합을 명확하게 걸러내고 신뢰성 있는 검증 결과를 얻을 수 있었습니다.

### 3-2. 성능 분석 및 시간 복잡도($O(N^2)$) 해석

각 크기별 MAC 연산을 I/O 제외 10회 반복 측정한 평균 결과는 다음과 같습니다.

| 크기 ($N \times N$) | 평균 시간 (ms) | 연산 횟수 ($N^2$) | 3×3 대비 연산량 배수 | 3×3 대비 시간 배수 |
| :------------------ | :------------: | :---------------: | :------------------: | :----------------: |
| **3×3**             |     0.0042     |         9         |        1.0배         |       1.0배        |
| **5×5**             |     0.0087     |        25         |        2.8배         |       2.1배        |
| **13×13**           |     0.0417     |        169        |        18.8배        |       9.9배        |
| **25×25**           |     0.0903     |        625        |        69.4배        |       21.5배       |

- **시간 복잡도 근거:** `mac_operation`은 $N$개의 행과 각 행의 $N$개 열을 이중 반복문으로 순회하며 1회당 곱셈과 덧셈을 수행하므로 총 연산 횟수는 정확히 $N^2$에 비례합니다. 따라서 알고리즘의 시간 복잡도는 **$O(N^2)$**입니다.
- **측정 결과 해석:** 크기가 3×3(9회)에서 5×5(25회), 13×13(169회), 25×25(625회)로 커질수록 평균 연산 시간도 0.0042ms → 0.0087ms → 0.0417ms → 0.0903ms로 뚜렷하게 증가했습니다.
- **이론 배수와 실측 배수의 차이:** 25×25의 연산 횟수는 3×3의 약 69.4배이지만 실제 소요 시간은 약 21.5배 증가에 그쳤습니다. 이는 작은 크기(3×3)에서는 순수 연산 시간보다 Python 함수 호출 오버헤드와 반복문 초기화 비용이 차지하는 비중이 크고, 크기가 커질수록 고정 오버헤드가 희석되며 $O(N^2)$ 연산 비중이 지배적으로 나타나기 때문입니다.
